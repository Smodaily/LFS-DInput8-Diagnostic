СБОРКА DLL ЧЕРЕЗ GITHUB ACTIONS (Visual Studio на компьютере не нужна)
======================================================================

1. Создай аккаунт на github.com (если его ещё нет).
2. Нажми + -> New repository. Название, например: LFS-DInput8-Diagnostic.
   Выбери Public или Private, затем Create repository.
3. На странице пустого репозитория нажми "uploading an existing file".
4. Распакуй этот архив и перетащи ВСЕ файлы и папки из него в окно GitHub.
   Важно: загружай содержимое папки проекта, включая скрытую папку .github.
   Если .github не отображается в Проводнике, включи показ скрытых элементов.
5. Нажми Commit changes.
6. Открой вкладку Actions. Если GitHub спросит разрешение на запуск workflows,
   подтверди его.
7. Выбери workflow "Build LFS DInput8 Diagnostic DLL" и нажми Run workflow.
   Если workflow уже запустился автоматически после Commit, просто открой его запуск.
8. Дождись зелёной галочки (Success), открой завершённый запуск и внизу
   раздел Artifacts. Скачай LFS-DInput8-Diagnostic-x64.zip.
9. Распакуй его: внутри будет dinput8.dll.

УСТАНОВКА ДЛЯ ПРОВЕРКИ
----------------------
1. Полностью закрой LFS.
2. Убедись, что рядом с LFS.exe нет уже существующей dinput8.dll.
   Если есть — НЕ перезаписывай её; сообщи об этом.
3. Положи диагностическую dinput8.dll рядом с LFS.exe.
4. Запусти LFS, открой настройки контроллера и подвигай левый стик.
5. Закрой игру и проверь, появился ли LFS_Assist.log рядом с DLL.
6. Пришли мне содержимое LFS_Assist.log.

ВАЖНО
-----
Это только диагностическая DLL: она пока не изменяет ось руля и не содержит
сам алгоритм подруливания. Её задача — проверить, вызывает ли LFS DirectInput 8.
Если игра не загрузит нашу прокладку или не вызовет DirectInput8Create, это
само по себе ещё не доказывает, что игра не использует DirectInput: тогда
проверим другой способ получения ввода.

После проверки DLL можно удалить из папки игры. Исходники остаются в репозитории.
GitHub Actions хранит собранный ZIP-артефакт 14 дней; скачай его сразу после сборки.
